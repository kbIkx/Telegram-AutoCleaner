# Проверка AutoCleaner 1.1.0

Дата: 25 октября 2026 года.

Окружение проверки: Windows, CPython 3.12.14, aiogram 3.31.0,
aiosqlite 0.22.1, python-dotenv 1.2.2, pytest 9.1.1,
pytest-asyncio 1.4.0, Ruff 0.17.2.

## Результаты

- `python -m pytest -q` — **83 passed**, 4.77 секунды.
- `python -m compileall -q bot run.py tests` — успешно.
- `ruff check .` — All checks passed.
- `ruff format --check .` — форматирование проверено.
- `uv pip check` — совместимость установленных зависимостей проверена.
- Импорты основного модуля и Dispatcher — успешно.
- Запуск без `.env` — ожидаемое безопасное завершение с кодом 1,
  без вывода токена и необработанного исключения.

Для воспроизводимой установки runtime-пакеты и транзитивные зависимости
зафиксированы в `requirements-lock.txt` с SHA-256.

## Проверенные сценарии

Дополнительно в версии 1.1 проверены: изоляция разных тем одной супергруппы,
отдельная обработка General, отказ при неизвестной теме, отмена очереди при переносе
очистки в другую тему, повторная проверка области перед удалением, автоматическая
остановка прежней очистки всей группы при обнаружении форума, сохранение привязки
после перезапуска, миграция схемы 1 → 2 без потери настроек и статистики, проверка
администратора при выборе темы командами и callbacks и отправка ответа в нужную тему.

- Сообщения администраторов и владельца не ставятся в очередь.
- Сообщения участников удаляются после срока; раннее удаление не происходит.
- Очередь и настройки сохраняются после закрытия и повторного открытия SQLite.
- `/disable` отменяет очередь, `/enable` включает только новые сообщения.
- Повторный `/enable` не сбрасывает временную границу обработки.
- Смена задержки сохраняет сроки старых задач; группы изолированы.
- Дубликаты сообщений и параллельные ticks не дублируют удаление.
- Повышение автора до администратора сохраняет сообщение.
- Сообщения самого бота, анонимные отправители, каналы, служебные
  и неизвестные сообщения сохраняются.
- Каждый элемент фотоальбома получает отдельную задачу.
- События закрепления и последнее закрепление из `getChat` защищаются;
  повторный update не возвращает защищённое сообщение в очередь.
- NetworkError, RetryAfter, Forbidden, отсутствие сообщения и постоянная
  ошибка удаления не останавливают обработку другой группы.
- Непроверяемый автор вызывает ограниченные повторы и безопасное сохранение.
- Просроченные задачи снимаются без запроса удаления.
- Потеря прав бота выключает очистку и отменяет очередь.
- Миграция переносит настройки и отменяет небезопасные старые IDs;
  повторное событие и старый update не воссоздают мигрировавший чат.
- Участники не могут выполнять административные команды или читать статистику.
- Некорректные `/settime` отклоняются, допустимые интервалы разбираются.
- Callbacks повторно проверяют администратора и редактируют существующее сообщение.
- Подстановка chat_id, поддельная панель и старые кнопки утратившего права
  администратора не позволяют менять настройки.
- Удаление бота из чата отменяет задачи.
- Старт приложения, настройка команд, получение обновлений и корректное
  завершение проходят с подменённым Telegram API.
- Отсутствующий токен, относительные пути конфигурации, маскирование секретов
  и блокировка второго процесса проверены отдельно.

## Границы проверки

Все Telegram-запросы в тестах подменены; SQLite используется настоящая.
Настоящий токен не применялся. Работа в реальной Telegram-группе,
доставка событий закрепления на стороне Telegram и запуск systemd на Linux
не проверялись. Известные ограничения Bot API и инструкция ручной проверки
описаны в README.
